# Agent Cowork Control 如何工作

这份文档面向希望进一步了解协作方式的用户。日常使用不需要记住术语，也不需要学习固定命令。

## 1. 先看任务能否拆开

如果目标单一、范围明确，没有可以单独拆出的部分，主 Agent 直接完成即可。

资料、步骤或文件较多，而且其中包含可以独立完成的检索、整理、比较、核查或执行工作时，可以交给多个助手分工。

协作有两种做法：

- **普通分工**：任务可以拆开处理，不需要额外检查计划和最终结果。
- **加强协作**：任务重要、复杂、内容很多，或容易遗漏和跑偏，需要额外的质量保障。开始前由另一名助手检查计划，执行中明确分工和交接，完成后再独立检查结果。

正式数据、权限、外部系统、高风险或难以回退的操作，仍然严格遵守项目和平台的安全规则；这些条件本身不自动决定采用哪种协作方式。

## 2. 三档对照

以下例子用于理解边界，不要求机械套用。

### 不启用协作

- 查询一个明确事实；
- 阅读或修改一个范围清楚的文件；
- 完成不需要拆分的单一步骤任务。

### 普通分工

- 分别从几个独立来源收集资料后统一汇总；
- 把一批文件分开提取相同字段；
- 分别比较几家公司、产品或方案，再由主 Agent 综合。

### 加强协作

- 基于大量资料形成重要的投资、战略或产品判断；
- 完成长篇报告、研究成果或大型创作，并保持统一主线；
- 处理多个部分相互影响的复杂任务，遗漏或偏差会明显损害最终结果。

区别不在任务属于什么类型，而在任务是否需要拆分，以及其重要性、复杂度和出错风险是否值得增加计划检查与结果检查。

## 3. 计划与确认

普通多步骤任务和普通分工使用简短的“步骤 → 验证”计划。主 Agent 说明准备做什么、怎样检查结果，用户确认后开始执行。

加强协作使用更完整的计划，明确目标、范围、分工、交接、验证方法和停止条件。计划需要用户确认，并在执行前接受一次独立检查。

如果目标、范围、质量要求或交付结果发生实质变化，主 Agent 会重新说明变化并请求确认，不会沿用原批准继续扩大任务。

## 4. 分工和交接

每个部分只有一个负责人，避免重复调查或多人同时修改同一内容。需要依赖其他助手结果时，任务说明会写清输入来自哪里、完成后交给谁。

主 Agent 始终负责整体判断、结果整合、处理冲突和最终回复。子 Agent 不替用户作最终决定，也不继续创建更多下级助手。

加强协作执行中出现交接延迟、结果冲突、关键缺口或助手失败时，主 Agent 会及时协调并说明影响，不让任务在后台静默中断。

## 5. 权限和安全单独处理

只需要阅读和检查的助手获得只读权限；只有明确负责修改内容的助手获得相应写入权限。指定某个模型或 Agent 不会自动扩大权限。

出现权限不足、目录归属不明或写入范围冲突时，受影响的工作会停止，而不是自行扩大权限、覆盖文件或合并未知改动。

这些安全要求适用于所有任务，不用来区分普通分工和加强协作。

## 6. 风险调用先试一次

已知、单次、只读且结果可以直接核对的调用，可以直接执行。

批量处理、写入操作、返回结构或权限不确定、成本较高，或者失败会明显影响数据和交付时，先用最小参数做一次小范围试运行，确认工具、权限和返回结果正常后，再继续正式处理。

是否需要试运行由调用本身决定，与采用普通分工还是加强协作无关。试运行失败后不会擅自更换来源、扩大权限或降低证据标准。

## 7. 文件和交接记录按实际需要使用

普通源码、文档、报告、演示文稿、表格或网页，由单一写入者直接写入已授权的目标目录。

需要多个助手分别写入不同内容、处理批量或正式数据、保留能够重新生成并核对的依据，或者把中间文件与最终交付分开时，才使用独立工作目录。

只有任务以后可能需要继续、需要跨会话恢复、需要汇总多项产物，或用户明确要求正式证据包时，才维护专门的交接文件。

工作目录和交接文件由实际产物决定，不会自动把普通分工升级为加强协作。

## 8. 交付前检查

普通分工由执行者检查自己负责的部分，再由主 Agent 依据已确认的范围和成功标准验收。

加强协作在执行后增加一次独立结果检查。检查发现问题时，由主 Agent 负责修正，并重新运行可以重复核对的检查；除非用户明确要求，不会反复增加独立审核。

结果还没有完成验证时，主 Agent 会明确说明，不会提前宣称完成。
