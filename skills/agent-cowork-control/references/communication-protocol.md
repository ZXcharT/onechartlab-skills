# 沟通与升级协议

本文件是 Agent Cowork 沟通状态、通知时序与恢复边界的完整定义。命中任一沟通事件前必须从主 Skill 指定的相对路径加载本文件。

## 状态与事件

统一状态：`RUNNING / RECOVERING / BLOCKED / FAILED / NEEDS_REVISION / NEEDS_USER_DECISION / COMPLETED`。

| 事件 | 触发 | 发送后动作 |
|---|---|---|
| `STATUS_REPORT` | 关键阶段、重要发现、可安全恢复的异常及恢复结果 | 继续执行，不等待回复 |
| `DECISION_REQUEST` | 分支选择会影响目标、成本、结论可信度、风险或不可逆动作 | 暂停相关分支等待 approver；无依赖工作可继续 |
| `REAPPROVAL_REQUIRED` | 范围、方向、风险、交付目标、权限边界或外部影响实质变化 | 暂停受影响执行，提交修订 Plan 等待批准 |

`FAILED / BLOCKED / NEEDS_REVISION` 是状态，不自动等于等待批准。是否暂停取决于能否在已批准范围内安全恢复。

## 子代理回传

关键状态不得只留在日志。子代理返回：

```markdown
### COMMUNICATION_EVENT
- status：RUNNING / RECOVERING / BLOCKED / FAILED / NEEDS_REVISION / NEEDS_USER_DECISION / COMPLETED
- event：STATUS_REPORT / DECISION_REQUEST / REAPPROVAL_REQUIRED
- 发生事项：
- 影响范围：
- 已完成内容与证据路径：
- 恢复建议：
- 可否在批准范围内安全继续：是 / 否
- 是否需要 approver 决定：否 / 是（问题与选项）
```

## 用户可见通知责任链

1. 子代理或后台任务命中 `BLOCKED / FAILED / NEEDS_REVISION / NEEDS_USER_DECISION` 时，结构化回传父代理。
2. 最接近用户的主代理负最终通知责任。收到结果后，在继续受影响的生产动作前说明发生事项、影响、处理方案和是否需要决定。
3. 平台已自动展示失败结果时，主代理仍需确认影响与后续动作。
4. 父代理不可用、不可达或回传失败时，受影响流保持 `BLOCKED`；保存错误证据、已完成内容和恢复入口，通过平台当前可用的上层可见状态通道输出受限失败状态。
5. 用户可见投递仍失败时，保持可恢复硬阻塞；下一次恢复可见交互时优先补报。在此之前不得继续恢复、返修、生产、交付或绕过最终回复屏障。

## 最低必报节点

受控协作至少在以下阶段发送简短报告：

1. Plan 与审查完成，正式启动生产执行；
2. 进入预计较长的异步或批量阶段，说明范围与下一验收点；
3. 关键证据或取数完成，说明覆盖、缺口及判断变化；
4. 进入正式综合、构建或验证；
5. 关键依赖失败、范围变化、验证 `NEEDS_REVISION` 或无法继续；
6. 验证通过并最终交付。

普通工具调用、无影响的局部格式修复、首次影响很小且可逆的重试不单独汇报。阶段报告只写状态、关键变化、问题、下一步和是否需要决定。

## 静默恢复边界

- 仅局部、可逆、影响很小，且不换源、不改口径、不扩权、不降级可信度的故障，允许一次自动恢复。
- 首次恢复成功且不影响范围或质量时，在下一关键阶段摘要披露，不单独请求批准。
- 相同错误第二次出现，或恢复需要替代来源、扩大工具、缩小交付、改变口径、降低可信度、增加外部影响时，禁止静默恢复；立即报告并按需升级。
- 子代理整体失败后，主代理须先报告事故与恢复方案；若恢复仍在批准范围内，可报告后继续，无需等待。

## 最终回复屏障

只有已批准 Plan 明确安排独立审核，或主代理已经派出验证助手时，才启用最终回复屏障。屏障只阻止未验收的最终完成结论，不得阻止或延迟阶段报告、事故通知、决策请求和重新审批；`DRAFT / VALIDATING / NEEDS_REVISION` 保持阻塞，主代理裁决为 `ACCEPTED` 后解除。未进入独立审核的任务不启用该屏障。

## 协议加载闭环

- 唯一相对路径：`references/communication-protocol.md`。
- 命中任一沟通事件前必须成功加载本文件。
- 加载失败时停止事件对应执行流，向父代理回传 `BLOCKED`；不得依靠主文件摘要推进恢复、返修或交付。
- 只允许执行主文件已完整定义的安全动作：保持硬停止、保存状态、尝试用户可见地报告加载失败。
