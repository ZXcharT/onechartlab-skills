# Agent Cowork Control 如何工作

这份文档面向希望进一步了解协作机制的用户。日常使用不需要记住其中的术语，也不需要学习固定命令。

## 1. 先判断是否需要协作

简单、明确且由一个 Agent 可以低成本完成的任务，直接执行即可。

只有当任务能够自然分成两个以上互不重复的部分，而且分开处理确实能并行推进、利用不同专长或从不同角度核查时，才启用协作。协作有两种做法：

- **普通分工**用于各部分边界清楚、风险较低的任务；
- **加强协作**用于涉及关键决定、高风险或难以回退的操作、需要多个助手分别写入不同部分、正式数据、权限、外部系统或正式验收的任务。它比普通分工多两步：执行前由另一名助手检查计划，完成后再独立检查结果。

任务步骤、资料来源或文件数量本身，不构成启用协作的理由。

## 2. 计划与确认

普通多步骤任务和普通分工使用简短的“步骤 → 验证”计划。主 Agent 说明准备做什么、怎样检查结果，用户确认后开始执行。

加强协作使用更完整的计划，明确目标、范围、分工、风险、验证方法和回退方式。计划需要用户确认，并在执行前接受一次独立检查。

如果目标、范围、数据来源、权限或风险发生实质变化，主 Agent 会重新说明变化并请求确认，不会沿用原批准继续扩大任务。

## 3. 每个助手负责明确的一部分

主 Agent 可以把研究、数据处理、文件修改和结果检查交给不同助手。用户指定助手时优先使用；否则根据子任务选择合适的专业助手。没有合适角色时，使用与当前 Agent 相同角色的临时助手。

每个部分只有一个负责人，避免重复调查或多人同时修改同一内容。主 Agent 始终负责整体判断、结果整合和最终回复；子 Agent 不替用户作最终决定，也不继续创建更多下级助手。

## 4. 权限按实际需要分配

只需要阅读和检查的助手获得只读权限；只有明确负责修改内容的助手获得相应写入权限。指定某个模型或 Agent 不会自动扩大权限。

出现权限不足、目录归属不明或写入范围冲突时，受影响的工作会停止，而不是自行扩大权限、覆盖文件或合并未知改动。

## 5. 高风险调用先小范围确认

已知、低成本、单次只读且结果可以直接核对的调用，可以直接执行。

批量处理、写入操作、返回结构或权限不确定、成本较高，或者失败会明显影响数据和交付的调用，需要更严格的控制。普通分工遇到这类调用时，会先转为加强协作；加强协作会用最小参数做一次小范围试运行，确认工具、权限和返回结果正常后，再继续正式处理。

如果试运行失败，流程会停止并说明原因，不会擅自更换来源、扩大权限或降低证据标准。

## 6. 文件与证据按需要隔离

普通源码、文档、报告、演示文稿、表格或网页，由单一写入者直接写入已授权的目标目录，不额外创建运行目录。

只有需要多个助手分别写入不同内容、处理批量或正式数据、保留能够重新生成并核对的依据，或者把中间文件与最终交付分开时，才使用独立运行目录。只有任务以后可能需要继续、需要跨会话恢复、需要汇总多项产物，或用户明确要求正式证据包时，才维护专门的交接文件。

普通分工中如果出现上述目录或交接需求，会先转为加强协作。这些文件用于保存证据和状态，不能代替真实验证、用户批准或发布授权。

## 7. 出现问题时及时说明

工具不可用、证据冲突、权限不足或工作范围改变时，主 Agent 会说明发生了什么、影响哪些部分，以及是否需要用户决定。

局部、可撤销且不影响既有批准的问题，可以在原范围内修复。需要更换来源、扩大权限、改变目标或显著增加风险时，必须停止并重新确认。

## 8. 交付前检查

普通分工由执行者检查自己负责的部分，再由主 Agent 依据已确认的范围和成功标准验收。

加强协作在执行后进行一次独立结果检查。检查发现问题时，由主 Agent 负责修正，并重新运行可以重复核对的检查；除非用户明确要求，不会反复增加独立审核。结果还没有完成验证时，主 Agent 会明确说明，不会提前宣称完成。
