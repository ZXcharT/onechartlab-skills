# Agent Cowork Control 如何工作

这份文档解释 README 中没有展开的工作原理。普通使用不需要记住这些术语。

## 1. 先判断任务是否值得分工

简单问题直接完成。只有当任务包含多个阶段、多个来源、多个文件，或者结果需要额外检查时，才启用协作流程。

## 2. 先给用户看计划

对于复杂或影响较大的任务，主 Agent 会先说明：

- 要解决什么问题；
- 会检查哪些内容；
- 准备怎样分工；
- 最终交付什么；
- 怎样判断已经完成；
- 哪些方向需要用户决定。

用户确认后才进入正式执行。计划发生实质变化时，需要重新确认。

## 3. 不同助手各自负责一块

主 Agent 可以把研究、数据处理、文件修改和结果检查分给不同助手。每块工作只有一个负责人，避免多人同时修改同一文件或重复查询同一批资料。

主 Agent 始终保留最终责任：子 Agent 不直接替用户下结论，也不能继续创建更多下级助手。

## 4. 权限按任务需要分配

只需要阅读和检查的助手获得只读权限；只有明确负责修改文件的助手获得写入权限。指定某个模型或 Agent 不会自动带来更多权限。

## 5. 先做小范围试运行

调用结构化数据工具前，会先用最小参数确认工具、权限和返回格式正常。维护文档中将这一步称为 Canary（小范围试运行）；普通使用不需要记住这个名称。

如果试运行失败，流程会停下来说明原因，不会擅自换数据源、扩大权限或安装依赖。

## 6. 文件和证据分开保存

复杂任务会使用独立运行目录，保存原始资料、处理结果、测试记录和最终文件。这样可以检查结果从哪里来，也能避免多个任务互相覆盖。

## 7. 出错时先告诉用户

工具不可用、证据冲突、权限不足或工作范围改变时，主 Agent 会说明发生了什么、影响哪些部分，以及是否需要用户决定。

局部、可撤销的小问题最多自动修复一次。需要换来源、扩大权限或改变目标时，必须停下来确认。

## 8. 交付前检查

重要任务在交付前会检查真实文件、测试结果和关键结论。检查发现问题后，由主 Agent 负责返修和重新确认，不会无限增加审核轮次。
