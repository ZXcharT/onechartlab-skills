# T01–T14 行为契约

本契约列出公开版不可退化的行为。仓库源码中的标准库测试会为每条规则运行至少一个允许场景和一个阻断/替代场景；单独安装 Skill 时，本文件仍提供完整规则索引。

| ID | 行为 | 必须通过 | 必须阻断或改道 |
|---|---|---|---|
| T01 | 三档协作与 Plan | 没有可独立拆分部分的任务直接完成或使用普通单 Agent Plan；可拆分的普通任务以轻量协作和简短“步骤 → 验证”计划执行；在能够拆出相对独立部分的前提下，重要、复杂、内容很多、容易遗漏跑偏或明确要求独立检查的任务使用受控协作，以六段 Plan 同时通过 approver 确认和独立 read-only 新 thread 审查后执行 | 任务结构与模式不匹配时改道；简短计划未确认，或受控 Plan 缺少任一确认、身份、权限或独立 thread 时等待批准 |
| T02 | 身份路由与 thread | 用户指定优先；否则选择合适专业 Agent；没有合适角色时使用当前角色创建新子 thread | 用户指定不可用、跨角色复用 thread、静默替换或未批准模型覆盖 |
| T03 | 最小权限 | 研究/验证/审查 read，唯一写者 write | read 角色获得 write |
| T04 | Canary 按调用风险触发 | 已知、单次、只读且结果可直接核对的调用在任一模式直接执行；批量、写入、结构或权限不确定、高成本或高影响调用在任一模式都必须先通过同 thread Canary | 风险调用未探测、探测失败、换 thread、换工具范围或换源时阻断；调用风险不得自动改变协作等级 |
| T05 | 已分配工作的补充查询 | 轻量协作中继续原 thread；受控协作中进入 `QUERY_BACKLOG`；新的独立方向可查询 | 任一模式重复派人处理已有部分时阻断 |
| T06 | 写入路径按产物决定 | 只读任务直接通过；普通交付在授权目标目录由单一写入者完成；任何模式需要隔离时，都以授权 run_root 和互不重叠目录处理多人写入、批量或正式数据、独立可重跑证据及需隔离的中间文件 | 协作等级不得替代目录授权；目标未授权、写入者或归属冲突、缺少授权 run_root、目录重叠或每目录多写者时阻断 |
| T07 | 完成与交接分开判断 | 直接任务、普通计划任务和轻量协作在成功标准满足且主代理验收后交付；受控协作还必须完成一次独立结果审核并由主代理裁决为 ACCEPTED；任一模式需要 FINAL 时都必须检查其完整性和真实性 | 成功标准未满足、受控结果审核未完成，或应有 FINAL 但缺失、不完整或失真时保持最终回复阻断；FINAL 不自动改变协作等级 |
| T08 | 状态汇报 | STATUS_REPORT 后继续安全无依赖工作 | 将状态报告误作审批请求 |
| T09 | 失败穿透 | 后台失败向用户可见层报告 | 只写内部日志或报告前继续生产 |
| T10 | 受限恢复 | 首次局部可逆故障恢复一次 | 第二次同错、换源、扩权或降级 |
| T11 | 加强协作的 NEEDS_REVISION | 默认由主代理接管返修和可重复核对的检查；approver 明确授权时可增加一次审核 | 未获额外审核授权却再次派审，或审核未完成便直接接受时阻断 |
| T12 | 重新审批 | 实质变化触发 REAPPROVAL_REQUIRED | 以普通状态报告替代批准 |
| T13 | 受控沟通协议加载 | 受控协作在事件前加载唯一协议源；其他模式不要求加载完整协议 | 受控协作未加载即处理事件 |
| T14 | 受控协议加载失败硬阻断 | 受控协作协议缺失时保持 HARD_BLOCK；其他模式不进入该状态机 | 受控协作依赖摘要恢复、返修、生产或交付 |

这些测试验证公开策略模型和 trace 合约，不代表宿主运行时提供系统级强制安全。宿主若有更强的权限或状态机机制，可以在不削弱本契约的前提下加固。
