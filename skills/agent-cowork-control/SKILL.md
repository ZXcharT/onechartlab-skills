# Agent Cowork Control

主代理统一负责，子代理按功能协作。

## 启用、模式、配置与加载

是否协作取决于独立责任域和实际收益，不取决于来源数量本身：

- **轻量协作**：任务可拆成两个以上独立责任域，且并行、专业分工或反证研究有明确收益。开始前提交简短的“步骤 → 验证”计划并获得用户确认；任务说明只需清楚的目标、责任边界、来源范围、返回要求和停止条件，不触发独立 Plan 审查、Canary、运行目录、`FINAL.md` 或正式验收状态机。
- **受控协作**：已有明确协作收益的任务涉及方向或关键口径决策、高风险或难回退执行、多个写入责任域、正式数据生产、权限或外部系统、正式独立验收时升级，使用本 Skill 的完整门禁。

单 Agent 可低成本完成的多来源查询、简单解释、单文件只读和无委派收益的小修走最简路径；拿不准时先简单，出现明确协作收益或风险再升级。

受控协作的每个获批 Plan 必须记录：

- `delegate_agent`：用户指定、按子任务职责选择的合适专业 Agent，或 `current-agent`。
- `plan_reviewer_agent`：按同一规则选择的 Plan 审查角色；必须使用独立新 thread 和 `read` 权限。
- `run_root`（仅命中写入隔离门槛时）：用户授权工作区中的运行根目录，默认 `<user-authorized-workspace>/runs/`。

用户明确指定 Agent 时优先使用；否则根据子任务职责选择合适的专业 Agent。没有合适角色时，继承当前 Agent 角色创建临时子 Agent。用户指定的 Agent 不可用时停止并报告，不静默替换。

轻量协作使用自包含的最小任务说明，不加载完整任务包和角色协议。受控协作执行前按顺序读取：

1. 先读 [任务包模板](references/task-packets.md)。
2. 再读对应角色协议：[执行协议](references/execution-protocol.md)、[研究协议](references/research-protocol.md) 或 [验证协议](references/validation-protocol.md)。
3. 命中任一沟通事件前，必须读唯一完整规范 [沟通协议](references/communication-protocol.md)。

受控协作的沟通协议加载失败时，停止受影响执行流并报告 `BLOCKED`；只允许保持硬停止、保存状态和报告加载失败，不得凭摘要恢复、返修、生产或交付。

## 核心规则

1. **主代理负责**：主代理规划、综合并最终验收；子代理不拥有最终回复，不创建下级代理。
2. **Plan 门禁**：单步、明确且小范围的任务可以直接执行。普通多步骤任务和轻量协作提交简短的“步骤 → 验证”计划，获得用户确认后执行，不触发独立 Plan 审查。受控协作提交六段决策 Plan，同时完成独立审查和用户确认后执行；具体触发条件见“启用、模式、配置与加载”。
3. **身份路由**：用户明确指定 Agent 时优先使用；否则根据子任务职责选择合适的专业 Agent。没有合适角色时，继承当前 Agent 角色创建临时子 Agent。新建专业 Agent 委派时传入所选身份；回退当前角色时省略 `agent` / `agentType`。默认继承所选角色的配置模型；只有用户明确批准时才覆盖。Agent 不可用时停止并报告。
4. **thread 独立**：Plan 审查、研究、执行和验证是不同角色；不同角色使用独立新 thread。仅同一责任域的续派使用原 `threadId`，同一 thread 不更换 Agent。
5. **最小权限**：研究、验证、Plan 审查默认 `read`；写权限只给明确写入责任人。身份或模型选择不得放宽权限、安全和验收边界。
6. **一个责任域一个执行者**：委派后主代理编排优先，不与子代理重复工作；受控协作的普通补充查询进入 `QUERY_BACKLOG`。
7. **Canary 按风险触发**：轻量协作不因委派本身触发 Canary。受控协作中，批量生产、写入、返回结构或权限不确定、高成本，或失败会实质影响数据与交付的结构化/MCP 调用，先在同一子线程做精确 Canary；低成本、只读、返回结构已知且结果可直接验证的单次调用可以直接执行。Canary 失败时停止受影响分支，不静默换源、扩权或降低可信度。
8. **证据外部化**：长数据、日志和表格落盘；主上下文只保留状态、路径、关键发现、冲突和缺口。高价值事实独立验证，关键数字用确定性断言，构建链可重跑。
9. **写入隔离按产物触发**：受控协作涉及多个写入责任域、批量或正式数据落盘、需要保留独立可重跑证据，或中间产物需要与最终交付隔离时，使用 `<run_root>/<time>-<slug>-<suffix>/`；不同写入责任域使用互不重叠的目录。单一写入者在 clean、明确授权的 Git 工作区或用户指定输出目录内完成普通源码、文档、报告、演示文稿、表格或网页时，不另建运行目录。只读研究和直接对话回答不使用运行目录。发现其他写入者、目录归属不明或写入范围重叠时立即停止，不自行合并或覆盖。
10. **FINAL 按交接触发**：`FINAL.md` 只用于需要持久交接、跨会话恢复、多产物汇总，或用户明确要求正式证据包的受控任务。运行目录存在本身不自动触发 FINAL；仅用于临时数据或过程隔离、且最终结果单一明确的任务可以不创建。需要 FINAL 时，由主代理在总任务根目录或用户指定的正式交付根目录维护唯一文件；子代理不分别创建。普通 Git 修改、单一文件交付、只读研究和直接对话回答不创建 FINAL。FINAL 只记录证据和状态，不替代真实验证、用户批准或外部发布授权。
11. **知情权独立**：状态汇报不等于征求批准；“批准后持续执行”不等于静默执行。子代理关键异常必须穿透到用户可见层，最接近用户的主代理负最终通知责任。
12. **规范层级**：本文件保留不可绕过的安全最小规则；各协议是受控协作相应场景的完整定义。冲突时先停止并修正规则，不选择宽松解释。

这些 Skill/prompt 门禁是政策约束；除非宿主另有硬执行机制，不宣称其为系统级强制安全。

## 受控协作的 Plan 双通道审查

轻量协作不进入本节。

1. 主代理形成 `PLAN_DRAFT`，同轮按身份路由规则派出 `read`、Plan 审查角色、独立新 thread 的审查者，并向 approver 展示六段 Plan。
2. 进入 `PLAN_REVIEWING` 后仅审查者可运行，不派研究、数据或执行任务。
3. approver 反馈与审查结果必须两方齐全；无回复不等于批准，不设超时默许。
4. “好的、开始执行、按这个计划做、没问题”等明确表述可视为批准。
5. 主代理裁决审查意见，approver 决定优先；冲突时列出并由 approver 裁决。
6. 非实质补充可修订后执行，不再次审查；范围、方向、风险或交付目标实质变化必须二次确认，批准后的新 Plan 阶段可审核一次。
7. 审查后立即关闭 reviewer thread；后续研究、执行、验证使用各自新 thread。简单任务不触发此审查。

## 路径与委派

- **A 直接完成**：单 Agent 可低成本完成或无委派收益。
- **B 轻量研究协作**：read 研究者按独立证据域查询、解释或反证，不重复拉取同一资料。
- **C 受控数据执行**：一个 write 数据执行者按风险决定直接生产或 Canary 后生产统一底稿；研究者读取同一底稿。
- **D 受控研究协作**：多个证据域需要统一口径、正式综合或独立验收。
- **E 受控一般执行**：目标边界明确，按执行协议产出文件或代码。
- **F 受控分阶段闭环**：口径 → 单次取数 → 分域分析 → 综合 → 执行 → 验证 → 验收；按依赖推进，不机械遍历。

轻量协作使用自包含的最小任务说明，写明目标、责任边界、来源范围、返回要求和停止条件。受控协作建立唯一责任映射并构造完整任务包；子代理看不到主会话。无依赖、口径统一、无写冲突才并行。已有责任域的补充优先续原 `threadId`；续派沿用已绑定身份，不跨角色复用 thread；独立新方向才另派。等待期间主代理只做综合框架、验收、冲突和口径设计。仅关键阻塞、来源冲突、关键事实/验证或用户明确要求时，主代理可窄范围直查并记录用途和停止边界。验收前关闭不再需要的实例。

## 受控协作的沟通安全最小规则

轻量协作使用平台常规状态与失败反馈，不进入下述沟通状态机。

| 事件 | 触发摘要 | 动作摘要 |
|---|---|---|
| `STATUS_REPORT` | 关键阶段、重要发现、可安全恢复的异常 | 报告后继续，不等待 |
| `DECISION_REQUEST` | 分支会影响目标、成本、可信度、风险或不可逆动作 | 暂停相关分支等待 approver；无依赖工作可继续 |
| `REAPPROVAL_REQUIRED` | 范围、方向、风险、交付目标、权限或外部影响实质变化 | 暂停受影响执行并提交修订 Plan |

`FAILED / BLOCKED / NEEDS_REVISION` 不自动等于等待批准。仅局部、可逆、低成本且不换源、不改口径、不扩权、不降级的故障允许一次自动恢复；第二次同错、整体失败或恢复改变范围/可信度时禁止静默处理。完整状态、通知链、里程碑、回传模板和失败终态见沟通协议。

## 验证、失败与交付

轻量协作由主代理依据当前任务的成功标准验收，不进入正式验收状态机。受控协作中的高价值任务使用 `DRAFT → VALIDATING → ACCEPTED`，问题进入 `NEEDS_REVISION`。质量链为执行者自检 → 按需独立验证 → 主代理验收。同一阶段最多派出一次独立审核；审核结束后，返修、确定性检查与最终验收由主代理接管，不进行增量复核，也不再派审核助手。审核资格按已批准 Plan 阶段计算，不因返修、文件变化、补充证据、发现新问题或阶段重命名刷新；额外审核仅在用户明确授权时进行。

进入 `VALIDATING` 或派出验证助手后，最终回复屏障生效，不得开始用户可见的最终正文。屏障不阻止阶段报告、事故通知、决策请求或重新审批。用户主动索要时，只提供明确标注的未验证草稿。

首次局部可逆错误可恢复一次。工具/权限不匹配必须硬停止受影响分支并报告，仅未受影响工作可继续；连续两次同错、上下文超限、执行者整体失败或 Plan/口径错误，按沟通协议保存证据与恢复入口。换源、扩权、降级或实质变更必须请求决定或重新审批。关键异常不得只写内部日志或 FINAL。

只有 `ACCEPTED` 且最终回复屏障解除后，才发送最终完成回复。任务存在 FINAL 时，回复与其正式产物和验证状态一致；没有 FINAL 时，以实际产物、确定性验证和已批准范围为准。验证受阻时明确说明“产出已生成，验证未闭环”。

## 行为验收入口

整理或审计本 Skill 时，行为保持、规则优先级和安全护栏高于压缩与去重。必须覆盖 [T01–T14 行为契约](references/behavior-contract.md)：Plan 双通道、身份路由/thread、最小权限、Canary、QUERY_BACKLOG、运行目录、FINAL/验证门禁、状态汇报不停工、后台失败穿透、静默恢复、NEEDS_REVISION、超范围重审批、沟通协议正常加载、沟通协议加载失败硬阻断。规则映射中测试 ID 为空即阻断；删除项必须指向唯一规范来源并通过等价性审查。
